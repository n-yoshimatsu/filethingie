# 段階4 設定・認証・プラグインの移行

対象はPHP 8.3／8.5のEXPANDED構成です。さくらの実運用対象はPHP 8.3です。この段階では本番サーバーへの配置を行っていません。

## 変更する順序

1. 現在のアプリ、`config.php`、管理対象ファイル、SQLite DBを公開領域外にバックアップします。設定には認証情報が含まれるためGitへ追加しません。
2. 隔離した確認用ディレクトリへ新しいアプリを配置します。`dev/`・`artifacts/`・テスト用設定は配置しません。既存の`config.php`を新しいサンプルで上書きせず、以下の項目を個別に移行します。
3. Web側のPHP版・SAPI・拡張を確認します。CLIで8.3.36と表示されても、Web側と同一とは限りません。
4. 認証設定、管理対象ルート、プラグイン設定を確認し、新しいセッションでログインします。既存セッションと旧ログインCookieは引き継ぎません。
5. 段階5の実機受入で、ログイン、日本語名、アップロード、編集、取得、権限、必要なプラグインを確認してから本番切替を判断します。

## パスワード

主ユーザーは`PASSWORD_HASH`、追加ユーザーは`password_hash`へ変更します。ハッシュはPHPの`password_hash()`で生成し、`password_verify()`で検証します。ハッシュ文字列をパスワード欄に入力する方式ではありません。

端末のBashで次を実行します。入力は画面・コマンド履歴へ表示されません。`tools/hash-password.php`の場所は手元の配置に合わせてください。

```bash
read -r -s -p '新しいパスワード: ' ft_new_password
printf '\n'
printf '%s' "$ft_new_password" | php tools/hash-password.php
unset ft_new_password
```

表示されたハッシュを**単一引用符**で囲んで設定します。生成ツールは空文字、NUL、72バイトを超えるパスワードを拒否します。日本語などは1文字が複数バイトです。ハッシュやパスワードをチャットへ送る必要はありません。

```php
define('USERNAME', '管理者名');
define('PASSWORD_HASH', '生成したハッシュ全体');
define('ALLOW_LEGACY_PASSWORD', FALSE);

$ft['users']['追加ユーザー名'] = array(
    'password_hash' => 'そのユーザーのハッシュ全体',
    'group' => '既存グループ名',
);
```

既存の`PASSWORD`／`password`は、`ALLOW_LEGACY_PASSWORD`未定義またはTRUEの移行期間に限って利用できます。旧設定を自動書換えしません。全ユーザーを移行後、平文の定義を削除し、`ALLOW_LEGACY_PASSWORD`をFALSEにしてください。

`PASSWORD_HASH`／`password_hash`が存在する場合はそちらを優先し、空または無効でも平文へ戻りません。新サンプルはハッシュのみを許可します。空のサンプルのままではログインできません。パスワード変更・ユーザー削除後は次のリクエストで既存セッションを失効させます。

## セッションと操作方法

- ログイン成功時のセッションID更新、HttpOnly・SameSite=Lax、セッションIDの厳格な検証。
- セッションCookie名の変更による旧セッションの切離し。非操作30分または開始から8時間で再ログイン。
- HTTPS接続または設定`HTTPS=TRUE`でSecure属性。HTTPSで運用する場合は`HTTPS=TRUE`を指定。未検証の転送ヘッダーへの依存なし。
- `REMEMBERME`は廃止。MD5から作る旧Cookieを受け付けず、チェックボックスを削除。TRUEの旧設定には通知を表示。ブラウザーのパスワード管理機能で通常ログインを補助可能。
- ログイン・ファイル変更・管理操作を含むPOSTにCSRFトークンを要求。ログアウトもPOST。旧GETの変更URLはHTTP 405、トークン不一致は403。独自スクリプトはログイン画面のトークンとCookieを取得し、ログイン後に新トークンを取得する必要あり。
- `LOGIN=FALSE`でも変更操作のCSRF検証を実施。ただしDB管理・ログ閲覧／CSV／削除は、ログイン済みの主ユーザーに限定。

旧版へ復元する場合は、バックアップのアプリと設定を組で戻し、新たにログインしてください。ハッシュだけの新設定を、ハッシュ非対応の旧アプリに渡さないでください。ロールバックは旧版の問題も戻すため、切替前の隔離確認を優先します。

## 同梱プラグイン対応表

「無効化」は対応済み機能への読み替えではありません。旧ファイルは履歴・参照用に残しますが、ローダーで実行を停止し、有効化された設定には通知を表示します。

| プラグイン | 今回の状態 | 条件・移行方法 |
|---|---|---|
| search | 更新・検証対象 | 新jQuery、CSRF付きAJAX、既存設定の継続 |
| edit | 更新・検証対象 | 標準テキストエディター。スペース変換のチェック状態、元のLF／CRLF形式、通常／AJAX保存の整合。混在改行はフォームの形式に統一 |
| db | 更新・検証対象 | PDO SQLite必須。DBを公開領域およびすべての管理対象ルートの外へ移動。依存順を自動調整 |
| log | 更新・検証対象 | db必須。ログイン成否、ログアウト、アップロード、ダウンロードの記録。主ユーザー＋`viewlogs=TRUE`で閲覧・日付／種別フィルター・CSV・7か月超の削除 |
| zip | 更新・検証対象 | PHP zip拡張（ZipArchive）必須。外部unzipコマンド不要。拡張なしは通知して無効化 |
| config | 未対応・無効化 | 上流の保存関数欠落。設定・ユーザー・グループはバックアップ後に`config.php`を手動編集。新しいWeb設定編集機能の追加なし |
| fileinfo | 未対応・無効化 | 上流の旧SQLite APIと未完成の説明表示・更新。既存DB・説明データを削除せず保管。今回の版では表示・更新なし |
| tinymce | 旧連携を無効化 | 外部の旧TinyMCE API前提。標準editへ移行。現行TinyMCEとの新規統合は今回の範囲外 |
| editorck | 旧連携を無効化 | 外部の旧CKEditor API前提。標準editへ移行。外部エディター本体の動作確認なし |
| fckeditor | 旧連携を無効化 | 旧FCKeditor API前提。標準editへ移行 |

editの同時編集ロックは上流でコメント化された未実装機能です。ロックを更新したように見せるブラウザーの定期通信を停止しています。同時編集保護を実装済みとして扱いません。

## DB・ログ

例として、Web公開領域が`/home/利用者/www`なら、その外側の専用ディレクトリにDBを置きます。実際のホームパスとPHP実行ユーザーの権限に合わせてください。親ディレクトリは事前作成し、他ユーザーから読めない権限（例0700）にします。DBファイルは0600を要求します。追加ユーザーのDIR配下も避けてください。

```php
$ft['plugins']['db'] = array('settings' => array(
    'path' => '/実際の非公開パス/filethingie/ft_db',
    'flushtables' => FALSE,
));
$ft['plugins']['log'] = array('settings' => array('viewlogs' => TRUE));
$ft['plugins']['zip'] = TRUE;
```

`flushtables=TRUE`は主ユーザーによるテーブル削除を許可します。通常運用はFALSEを推奨します。旧SQLite 3のDBはコピーした上でパスを変更してください。旧DBからのデータ変換・本番DBの移行は未実施です。壊れたDBやスキーマ不整合は通知してDB／logを無効化し、元のDBを削除しません。SQLite 2形式の自動変換はありません。

logをdbより先に列挙してもdbから初期化します。拡張・権限・配置条件の不足では基本のファイル管理を継続します。CSVはセミコロン区切り、UTF-8、引用符を含む文字列を適切に出力します。表計算ソフトで式として扱われる先頭文字には単一引用符を付けるため、そのフィールドのCSV値は画面表示と異なります。

## ZIP

ZIPダウンロードは許可された通常ファイルとディレクトリを対象とし、シンボリックリンクを追跡しません。空ファイル、日本語名、空ディレクトリを保持します。

展開は`sample.zip`なら現在の場所の**新規`sample/`**に行います。旧版の現在フォルダーへ直接展開する動作からの変更です。同名の保存先があれば拒否します。絶対パス、親フォルダーへの逸脱、禁止拡張子、特別ファイル、重複、暗号化エントリーを拒否します。最大1,000エントリー、非圧縮合計MAXSIZE（MAXSIZE無制限時20MB）、全体容量LIMITも確認します。展開エラー時は今回作成した展開先を片付けます。

旧`filebuffer`／`active`設定は使用しません。ダウンロード用一時ファイルはPHPの一時領域で処理します。PHPのzip拡張と一時領域の書込み権限をWeb側で確認してください。

## ブラウザー・日本語

jQuery 4.0.0をローカル同梱し、CDNへの実行時接続を不要にしています。旧jQuery 1.2.1と旧TableSorter一式を削除し、ログ表の並替えはアプリ内で処理します。出所・ライセンスは[依存一覧](DEPENDENCIES.md)を参照してください。

引用符・HTML風文字列を含むファイル名はDOMのテキスト／値として設定します。ブラウザーのmultipartによる引用符の`%22`変換は、元名との照合を経て復元します。JavaScript無効時のアップロードでは、ブラウザーが変換した名前を受け取る制約が残ります。上流の日本語翻訳の文字化けを修復しました。

ローカルChromeでの機能確認と、さくら実機・利用ブラウザーでの総合受入は別です。段階5ではWeb側のPHP/SAPI、HTTPS、拡張、ファイル権限、DBの配置、必要なプラグインを確認します。URLからの取得、同時更新、全ブラウザー、全言語、すべてのサーバー制限までの保証は今回の結果に含みません。

## 段階5での追加変更

URLからの作成は`URL_HOSTS`未設定または空文字列の場合、無効になります。使用する場合のみ、設定配列へスペース区切りの正確なHTTPSホスト名を指定してください。cURLと公開IPv4が必要です。HTTPS443のみ、証明書検証あり、リダイレクトと既存ファイルの上書きは拒否します。MAXSIZEが0の場合もURL取得は20 MiBを上限にします。LIMITも取得前後に確認しますが、全リクエストを横断した容量割当の排他保証はありません。

同名アップロードは排他的な新規ファイル作成で競合を拒否します。編集ロックを追加する変更ではありません。HTTPSがWebサーバーから通知されている場合は、設定HTTPSがfalseでもリダイレクトをHTTPSのまま維持します。リバースプロキシ環境では従来どおりHTTPS=trueを設定してください。
