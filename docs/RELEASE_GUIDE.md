# File Thingie PHP 8.3／8.5版の導入・更新・復元

配布識別名は`php83-85-20261025`です。元のFile Thingie 2.5.7を更新したフォークです。ソース内のVERSIONは2.5.7を維持し、この配布識別名とmanifestで更新版を区別します。

ZIPの`app/`にある46ファイルがWebアプリです。開発用ツールや検証用アカウント、実際のconfig.php、Basic認証ファイル、保存データは含めていません。新規導入では必要な設定を作成し、既存環境では設定とデータを保全してから更新してください。

## 対応環境

- PHP 8.3／8.5、HTTPS、session／json。検証版は8.3.36／8.5.12です。
- さくらのレンタルサーバ・スタンダード、FreeBSD、WebのPHP 8.3.36（cgi-fcgi）で本番受入を行った構成です。さくらでのPHP 8.5の実機確認は含みません。
- DB／logはPDO SQLite、ZIPはZipArchive、URL取得はcURLが必要です。利用しない機能の拡張は不要です。
- CLIとWebのPHP版・拡張・設定は別々に確認してください。CLIでの表示だけではWeb側の条件を確認できません。

## 新規導入

1. 配布ZIPのSHA-256をSHA256SUMSと照合し、ローカルか非公開の作業ディレクトリへ展開します。manifest.jsonで各ファイルも照合できます。
2. 新しい公開ディレクトリへ`app/`の内容を配置します。入口はindex.phpです。ZIP全体やtools/を公開先へ配置する必要はありません。
3. 管理するファイル専用の保存ディレクトリを作成します。config.sample.phpを基にconfig.phpを作り、DIRをこの専用保存先に設定します。サンプルのDIR「.」のままアプリ本体と保存ファイルを混在させないでください。
4. アプリ内ログインを使う場合はUSERNAMEとPASSWORD_HASHを設定します。ハッシュはtools/hash-password.phpで生成します。Basic認証だけで使う場合は、先にWebサーバー側の認証を設定してからLOGIN=falseにします。認証のない公開先でLOGIN=falseを使用しないでください。
5. HTTPSを使用し、HTTPS設定、ファイル上限MAXSIZE、利用するプラグインと権限を設定します。アプリ用設定・DB・PHPログを非公開領域へ置き、WebのPHP実行ユーザーだけが読み書きできるようにします。CLIとWebが異なる利用者の場合、0600の設定ファイルをそのまま共有できません。
6. Webサーバー側で設定ファイル・認証ファイル・PHPログ・ディレクトリ一覧の直接取得を拒否します。保存ファイル経由でPHP等のスクリプトを実行させない設定も必要です。Webサーバーごとの設定方法を確認してください。
7. 未認証アクセスの拒否、ログイン、一覧、アップロード、ダウンロードした内容、編集・削除、PHPログを検証してから通常利用を始めます。

パスワードの生成例はBash用です。パスワードをコマンド引数や履歴へ残さず、標準入力で渡します。

```bash
read -r -s -p '新しいパスワード: ' ft_new_password
printf '\n'
printf '%s' "$ft_new_password" | php tools/hash-password.php
unset ft_new_password
```

出力されたハッシュを単一引用符で囲んでPASSWORD_HASHへ設定します。1〜72バイトのパスワードを使用してください。追加ユーザーや旧平文設定からの移行は[設定移行資料](https://github.com/n-yoshimatsu/filethingie/blob/php85-support/docs/STAGE4_MIGRATION.md)を参照してください。

## 既存環境の更新

既存フォルダーへZIP全体を上書き展開しないでください。

1. 現在の設定・保存先・認証・プラグイン・独自改修と、FTP等を含む書込み経路を把握します。
2. アプリ、設定、認証関連、保存データ、利用するDBを公開領域外に保全します。保全コピーの内容を照合し、新規の隔離ディレクトリへの復元も確認します。
3. 複製したデータと移行後設定を使い、別の場所で新版を検証します。独自の表示変更やプラグイン利用もこの時点で確認します。既存config.phpをサンプルで置き換えないでください。
4. 利用者のアップロード・編集が終了し、他の書込み経路も停止していることを確認します。入口をメンテナンス表示へ切り替え、Webからの停止応答を確認します。待ち時間の経過だけでは、既に進行していた処理の終了を判断できません。
5. 停止中の最新データ・ソース・設定・認証を新たにバックアップし、内容・権限・更新時刻を照合します。メンテナンス用入口と停止前の入口を区別して保管します。
6. 検証済みの更新対象だけを配置し、保存データを古いコピーで上書きしないでください。配置・設定・認証・保存データの一致とPHPログを確認してから入口を再開します。
7. 本番URLで、試験用に新規作成した専用フォルダー内だけを操作します。試験データを削除した後、保存データと停止時バックアップ、配備ファイル、PHPログを照合して通常利用へ戻します。

切替時の非公開準備フォルダーは、本番が参照する設定とPHPログの保存先でもあります。単なる一時ファイルとして削除せず、最終バックアップとともに保管してください。

今回のさくら向け切替ツールは、レビュー済みのBasic認証・DIR=filesまたは./files・表示変更と非公開準備計画に限定したものです。任意の環境にそのまま適用する汎用インストーラーではありません。[段階6の手順と対象範囲](https://github.com/n-yoshimatsu/filethingie/blob/php85-support/docs/STAGE6_CUTOVER.md)を確認してください。

## 復元

復元前に操作を止め、変更後に追加された最新データも保全します。ソースと設定を組で戻し、切替後の新しい保存データを古いバックアップへ巻き戻さないでください。内容・権限・更新時刻と認証範囲を再照合し、動作を確認してから再開します。

旧ソースはPHP 8.3で動作しないとの報告があります。旧ソースの復元だけではサービス復旧になりません。さくら向けツールのrollbackは元のプログラムと設定を復元し、入口は503のまま維持します。PHP 5.6への自動切替や、未検証の旧入口の自動公開は行いません。

保全・復元ツールの詳細は[バックアップ資料](https://github.com/n-yoshimatsu/filethingie/blob/php85-support/docs/STAGE6_BACKUP.md)を参照してください。保全用キットのrestoreは新規非公開ディレクトリへの隔離復元です。所有者、ACL、拡張属性、ハードリンク関係までの再現は検証範囲に含みません。

## 主な変更と残る制約

- パスワードハッシュ、CSRF検証、セッションID更新、アプリログインの30分無操作期限・8時間絶対期限に対応しています。Basic認証にこの期限を追加する変更ではありません。
- jQuery 4.0.0を同梱し、日本語名・空ファイルを扱えます。同名アップロードは既存内容を保持して拒否します。編集の同時ロック機能は未実装です。
- DB／logはPDO SQLiteへ対応しました。SQLite 2形式の自動変換と既存本番DBの移行は対象外です。
- ZIP展開先は新規の専用フォルダーです。親への逸脱、危険な名前、暗号化等を拒否します。
- URL取得は明示したHTTPSホストのみです。URL_HOSTSが未設定なら無効です。転送先制限や容量制限は設定移行資料を参照してください。
- 旧remember me、未完成のconfig／fileinfo、TinyMCE／CKEditor／FCKeditorの旧連携は無効です。設定のWeb編集や旧説明DBの表示を対応済み機能として扱っていません。
- 表示は設定で調整できます。全言語・全ブラウザー・あらゆるサーバー構成での動作を保証する検証ではありません。
