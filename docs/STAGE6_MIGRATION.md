## 作業順序と完了条件

1. 読取り専用棚卸し：認証設定の所在、LOGIN、管理ルート、ファイル数・容量、プラグイン宣言、独自改修の手掛かり、空き容量の確認。
2. 配布候補：段階5合格ソースを固定、index.php運用への配置構成、依存ライセンス、ファイル一覧とSHA-256、対応範囲の明記。
3. バックアップ：本番アプリ・設定・Basic認証関連・管理ファイル・既存SQLiteを含む対象確定、書込み停止中の整合した複製、公開領域外への保管とハッシュ検証。
4. 別配置への移行確認：本番保存データの複製でのリハーサル、相対パスの解決、Basic認証範囲、LOGIN=falseでの基本操作と内容保全の確認。既存SQLite 2形式は自動変換対象外。
5. 復元確認：複製した隔離環境でバックアップからの復元、対象ファイルと設定の一致。旧アプリはPHP 8.3で不動作との利用者報告があるため、ファイルを戻すこととサービス復旧の区別。PHP 5.6への本番切替を自動実行しない扱い。
6. 本番切替：棚卸し結果に基づく具体的な配置・戻し方・影響範囲の確定後、切替と再確認。既存データをサンプルで上書きする操作なし。
7. 正式配布：確認済みの版・残る制約・導入／更新／復元手順を添えたタグとリリース。

段階6全体の完了条件は配布・導入／更新／復元資料と検証、実施する本番移行の結果記録。棚卸しツールの完成を本番移行完了とする扱いなし。

## 読取り専用棚卸しツール

```text
php tools/sakura-inventory.php 本番アプリのディレクトリ ホームディレクトリ 公開ルート
```

設定PHPのinclude・evalなし。PHPのトークンを用いた単純リテラル代入の候補抽出、動的構文・未対応代入・関数呼出しの件数記録。実効設定値を確定したとする扱いなし。条件分岐や外部読込み、ユーザー／グループ内の設定、複合式は個別確認の対象。

.htaccessはアプリから公開ルートまでの祖先を読取り、Basic宣言・Require宣言・認証ファイルの存在と権限のみの出力。AuthUserFile／AuthGroupFile本文の非読取り、ユーザー名・パスワード・ハッシュ・フルパスの非出力。サーバー全体の認証設定や条件付きディレクティブの評価は対象外。

管理DIRは静的に読める候補だけのメタデータ集計。シンボリックリンクの非追跡、ホーム外の再帰読取りなし、5万エントリーまたは10秒の上限と不完全フラグ。保存ファイル名・本文の出力なし。Basic認証ファイルや設定の変更、既存users.shの実行、Web診断ページの作成なし。
