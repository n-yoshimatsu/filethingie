# 段階6 保全コピーと隔離復元

CLI専用キット。設定PHP、既存index.php、users.shの実行なし。本番への書込みなし。

## 保全コピー

```text
php sakura-backup.php backup APPLICATION_DIRECTORY HOME_DIRECTORY WEB_ROOT
```

対象は管理DIRがアプリ配下へ解決される静的設定、追加ユーザー／グループなしの今回の環境。未対応の式、動的設定、外部管理DIR、シンボリックリンク、特殊ファイル、特殊権限ビットがある場合は停止と個別確認。これは汎用の全PHP構成対応ツールではない範囲。

ホーム直下の新規`.ft-stage6-backup-日時-乱数`へ以下を保管。

- `app/`：隠しファイルと検証用サブフォルダーを含む既存アプリの全ファイル・全ディレクトリ。既存設定、Basic認証関連、保存データ、php.ini等も対象。
- `extra/`：公開ルートまでの上位.htaccess、およびアプリ・子フォルダー・上位.htaccessで参照する実在するホーム配下の認証ファイルのうち、app/内と重複しないもの。
- `manifest.json`：原配置・相対名・権限・更新時刻・内容ハッシュ。サーバー内部だけの保管対象。チャット・GitHubへの送信禁止。
- `COMPLETE.json`：コピーと照合の成功後だけの完了マーカー、manifestのSHA-256。
- `summary.json`：チャットに送信可能な結果要約。標準出力と同じ内容。

バックアップ内の全ディレクトリ0700、ファイル0600。元の権限・更新時刻はmanifestに保持。原本の権限・内容・名前・更新時刻の変更なし。読取りに伴うatime更新はOS次第。

コピー前後の原本ハッシュ・権限・更新時刻・ファイル構成と、コピーした全ファイルのハッシュを照合。停止済みの全書込み元をツールが保証する機構や原子的スナップショットではないため、今回の結果は移行前の保全コピー。最終切替では別途書込み停止と新しいバックアップが必要。

既存アプリには約1.15 GBの管理データがあり、最低でもその分とソース・検証用フォルダー等の追加空き容量が必要。disk_free_spaceはサーバーのファイルシステム空き領域であり、契約アカウントの残容量ではない値。書込み失敗・容量不足時はINCOMPLETEと新規フォルダー識別名の出力、原本の変更なし。部分コピーの自動削除なし、完了前の復元利用不可。

上流との比較は公開済みソースファイル名だけを出力。EXACT＝同一、LINE_ENDINGS_ONLY＝CRLFをLFへ揃えた内容が同一、MODIFIED＝差分の個別確認対象、MISSING＝その旧配布ファイルの不在。独自改修の有無をサイズだけから推測しない扱い。認証の未解決参照数は記録のみ、実効認証範囲の証明ではない値。

## 隔離復元

```text
php sakura-backup.php restore BACKUP_DIRECTORY HOME_DIRECTORY WEB_ROOT
```

完了マーカー、manifest、コピーしたファイル・権限・時刻の一致確認後、ホーム直下の新規`.ft-stage6-restore-日時-乱数`へ復元。内容・権限・更新時刻の照合、復元先親0700。元の所有者・グループ、ACL・拡張属性・ハードリンク関係の再現は対象外。同一アカウントでの内容と通常権限の復元用。

元の`.htaccess`には本番の絶対参照先が残るため、隔離復元物をそのままWeb公開する操作は禁止。アプリ実行・本番切戻し・URL公開・元ファイルの上書きなし。復元にはさらに保全コピーと同程度の追加容量が必要。

保全コピー後に原本が更新された場合、その更新は当該コピーに未反映。切戻し時の新規データ保全や稼働復旧確認は別途必要。
